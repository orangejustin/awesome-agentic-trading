# Contributing

Suggest a useful project, correct a fact, or remove a stale entry. No dependencies, accounts with data providers, or commands are needed to contribute.

## Easiest path

[Open an issue](https://github.com/orangejustin/awesome-agentic-trading/issues) with the repository URL, what someone would use it for, and one important limitation. Maintainers can fill in the remaining metadata.

## Edit an entry

Edit only [README.md](README.md), using an existing entry as your template. Include:

- A public upstream repository and one sentence explaining what it does and who it suits.
- Its documented mode: research, analysis, backtesting, paper trading or live-capable tooling. Label connectors clearly.
- A link to the actual root license and a dated commit from the default branch.
- One concrete caveat: setup requirements, missing data, platform limits, simulation-only behavior or order permissions.
- A README/documentation source at the same commit and the UTC date you checked it. If it differs from the list-wide date, add “Checked: YYYY-MM-DD” to that entry.

Use GitHub's browser editor or your preferred editor and submit a pull request. Refresh the list-wide check date only after rechecking every entry; no test command is required.

## Before submitting

Open your links, check that they support the text, and preview the Markdown. Use a commit's committer date, not the repository's last-updated or last-pushed date. Read the license text rather than inferring it from a badge.

Keep descriptions short and written in your own words. Prefer projects with a distinct use and readable setup instructions. Stars, return claims and affiliate links are not selection criteria. Disclose an affiliation with a project you suggest.

If a source is unavailable or unclear, say what is unknown instead of guessing. If a project becomes archived or its setup is obsolete, label that limitation or propose removing it. Do not submit credentials, private financial data or conversation transcripts.
